# XNOBrain agent usage contract

Implemented against GoRouter source revision `1a237fe` (implementation commit follows this document).

## Capability

Capability marker: `xnobrain-agent-usage-v1`.

GoRouter is authoritative for Router-accounted request, token, provider-cache,
Router-cache, and model-priced cost facts. XNOBrain remains authoritative for
editable agent budget preferences. This API supports a soft admission check; it
is not an atomic agent-budget reservation.

## Workload-bound keys

Create an API key with the existing authorized `POST /admin/api-keys` operation
and an optional immutable binding:

```json
{
  "name": "XNOBrain agent runtime",
  "models": ["cx/gpt-5.6-luna"],
  "scopes": ["chat", "usage:read"],
  "owner_type": "user",
  "owner_user_id": "user_123",
  "workload": {
    "application": "xnobrain",
    "environment": "production",
    "workspace_id": "workspace_123",
    "agent_id": "agent_123"
  }
}
```

`application`, `workspace_id`, and `agent_id` are required together. Values are
opaque stable IDs (maximum 128 bytes; letters, digits, `.`, `_`, `-`, `:`, `/`).
The binding is assigned only during authorized key creation and is not mutable
through key patch or inference. Rotation preserves it. Deleting or replacing a
key does not delete historical usage. Agent rename keeps the same ID; a clone
must use a new agent ID. Legacy keys remain explicitly unbound.

## Inference correlation

Send optional correlation in dedicated GoRouter headers:

```text
X-GoRouter-Conversation-Id: conversation_123
X-GoRouter-Run-Id: run_123
X-GoRouter-Parent-Run-Id: run_parent_123
X-GoRouter-Request-Id: request_123
```

Values use the same bounded opaque-ID character set. They do not authorize,
change ownership, or override the key binding and are not forwarded upstream.
A missing logical request ID is generated by GoRouter. A distinct provider
attempt ID is generated for every persisted accounting event.

## Weekly usage

```http
GET /admin/usage/agents/weekly?application=xnobrain&environment=production&workspace_id=workspace_123&agent_id=agent_123
Authorization: Bearer <agent-bound key>
```

Requires `usage:read`. Ordinary keys may query only their exact authenticated
workload binding. Filters narrow existing user/organization visibility. A
bounded comma-separated `agent_id` batch (maximum 100) is available only when
the authenticated authority permits those identities.

The response contains `period_start` and exclusive `period_end`, `timezone`,
`week_starts_on`, `as_of`, accounting/completeness state, attribution coverage,
and summary totals for requests, all four token components, all four model-cost
components, Router cache hits, and free/unpriced compatibility counters.

The period uses `quota.Window("week")`, including configured `WEEK_START`
(default Sunday UTC). `accounting_ts` is fixed at request admission, so work
finishing after a boundary remains in its admission week. General usage `until`
filters are half-open (`timestamp < until`).

## Accounting semantics and consistency

- `cost_usd` is Router model-priced cost, not a provider invoice.
- Missing configured prices remain Free/zero under the current Router policy.
- `usage_measurement` distinguishes normalized provider usage, Router-cache
  usage, and unknown usage.
- Provider cache reads/writes remain separate from GoRouter response-cache hits.
- Response-cache hits have zero provider cost.
- No prompt or completion capture is required or enabled by this feature.
- Agent-bound event IDs are idempotent in SQLite/PostgreSQL. ClickHouse
  serializes each agent-bound event ID through its configured distributed
  mutation lock and checks durable presence before insertion, preventing
  duplicate retry writes across replicas. Legacy unbound writes retain their
  existing batched behavior.
- The weekly endpoint returns durable settled rows only. It never merges a
  process-local pending map and therefore never double-counts pending writes.
  `freshness: settled_only` and `completeness: durable_records` state this
  contract. Backend failure returns 503 rather than a false zero.
- An authorized no-usage result returns zero totals with
  `attribution_coverage: no_usage`.

## Errors

- `400`: malformed or oversized agent/correlation filters.
- `403`: attempted binding broadening or missing object permission.
- `404`: key has no workload binding or the binding is concealed.
- `503` with code `usage_unavailable`: durable aggregation unavailable.

## Current limitations

GoRouter does not enforce a strict per-agent concurrent cap. XNOBrain performs a
soft pre-admission comparison. Agent-bound events bypass the volatile queue and are synchronously acknowledged by
the selected durable repository before accounting completion. Legacy unbound events
continue through the existing asynchronous queue; a process crash can lose those
accepted in-memory legacy records. Exact provider
invoice reconciliation is impossible when the provider does not report usage.
A durable queue/outbox for legacy unbound asynchronous events remains a follow-up
before claiming fully crash-safe accounting for every historical client path.

## Safe fixture

Use synthetic IDs such as `workspace_test`, `agent_test`, `run_test`; never put
emails, secrets, prompts, or mutable display names in workload/correlation IDs.
